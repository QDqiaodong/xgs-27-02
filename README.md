# xgs-27 短视频投稿脚本多评委加权自动分级评审系统

## 项目简介

短视频投稿脚本多评委加权自动分级评审系统，包含 Spring Boot 后端、Vue/Vite 前端、MySQL 与 Redis。

## 脚本双盲脱敏视图

系统内置完整的脚本双盲脱敏链路（`/api/scripts/**` + `/api/scripts/{id}/masking/**`）：

- **角色分视图**：管理员录入的原稿完整保留作者、来源机构、联系方式、正文与附件说明，管理员在受控详情中看到的仍是原稿（`masked=false`）；评委与查看员访问任何脚本入口（列表、详情、打分页、分配/回避/统计摘要）时，只能得到服务端从原稿派生的脱敏版本（`masked=true`），响应中不携带任何原始身份字段——篡改脚本编号、直接访问详情地址、前进后退、打印预览或下载页面都拿不到原文。
- **线索识别**：录入/编辑即扫描作者、来源、标题、正文、附件说明中的姓名、电话、邮箱、机构全称、社交平台账号（`MaskingService`）。电话/邮箱/社交账号整体替换，不留可猜的半截；与作者/来源完全一致的姓名、机构自动确认为投稿身份。
- **稳定代号**：同一脚本内同一身份的所有线索替换为同一代号（如“投稿人·问樵”），代号按（盐+脚本ID+身份ID）哈希生成——同一投稿人在不同脚本中代号不同，评委无法横向关联；相似姓名的不同身份（张三/张三丰）各自成为独立线索，绝不合并。
- **剧情人物保留**：与投稿身份无关的正文人名默认不误删；无法确定是否身份线索的片段（如正文中的陌生机构、作者名的相似长名）标为“待管理员核对”，核对完成前评委看到的是更保守的【待核对】占位符，不会先泄露再补救。
- **管理员核对**：`/script/:id/masking` 页面三分区展示原稿、识别线索、脱敏结果；管理员可将待核对线索确认为“投稿身份”（归属投稿人或新建独立相关身份）或“正文角色”，也可手工补充遗漏线索。确认只调整脱敏视图与映射，不改写原稿；每次查看映射与每次核对均写入审计记录（`audit_log`，module=Masking）。
- **持久一致**：线索与身份映射落库（`identity_clue`/`script_identity`），刷新、重新登录、重新扫描后结果一致；原稿编辑后重扫会保留已有核对结论并清理失效线索。
- 后端测试 `MaskingIntegrationTest`（11 项）与 `MaskingWebSecurityTest`（7 项）覆盖：元数据与正文线索识别、同一身份稳定替换、跨脚本不可横向关联、剧情人物保留、模糊线索保守隐藏与核对、映射查看与核对审计、评委/查看员/未登录的可见范围、篡改编号访问、编辑后重扫与手工补充线索。

## 评委利益冲突回避与替补接管

系统内置完整的评委回避链路（`/api/recusals/**`）：

- **申报**：评委在已分配脚本上可申报与作者 / 来源机构 / 题材（及其他）的利益关系，必须填写回避类型、说明与可核验依据；管理员可代评委申报。
- **可见范围**：普通查看员与非申报评委只能看到回避状态；敏感说明、依据、补充材料、审批理由仅申报本人与管理员可见。
- **审批**：管理员可批准、驳回、要求补充材料，每次处理均记录操作者、前后状态与理由（处理轨迹可审计）；管理员不能审批由自己代为提交的申请。同一申请被并发处理时通过行锁 + 乐观锁保证只有一个最终决定。
- **未决期间**：脚本仍可查看，但该评委不能提交新评分。
- **批准**：立即终止其分配（RECUSED），历史评分不删除而是标记无效并保留原文，从总分、极端分识别与等级计算中排除；已分级脚本撤销旧等级进入“待补评”。管理员再指定一名未参与该脚本、状态正常且专业方向匹配的替补评委接管（`uk_replaces_assignment` 保证不会重复创建替补分配）；替补评委仅看到接管后的任务，不继承原评委的评语草稿或敏感回避说明。
- **驳回**：恢复原分配状态与原评分有效性。
- **重新分级**：替补评分进入、有效评分重新达到 2 份后才能再次分级；分级事务与回避批准/替补打分共用同一把脚本行锁，最终等级只使用当时有效的评分，刷新或重新登录后状态一致。
- 后端集成测试 `RecusalIntegrationTest`（H2，13 项）覆盖申报、补充、审批、并发审批、替补接管、评分失效与恢复、事后回避撤销等级、重新分级与审计轨迹，以及管理员/评委/查看员三类角色的可见范围。
